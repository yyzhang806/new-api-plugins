# Changelog

## [1.2.0]

### Added

- 支持使用 v4.5 生成纯音乐，可调用 `/incho/api/v1/song/instrumental`，或在 Responses 的 metadata 中设置 `task_type: "instrumental"`。
- 支持使用 v3.5 仿写歌曲，参考音频可以是公网 URL 或网关歌曲 ID。使用网关歌曲 ID 时会校验归属，并沿用原歌曲的生成渠道。
- 新增 `incho_lyric` 独立歌词生成，可通过 `/incho/api/v1/lyric/generate` 或 Responses API 调用。歌词同步返回，每次成功生成计为一个单位。
- 新增 `/incho/api/v1` 下与开放平台路径对应的生歌和查询接口，支持一次查询多个网关任务 ID。返回的歌曲 ID 可用于后续仿写。
- 新增 `/incho/api/v1/task/cancel`，通过 `incho_cancel` 取消调用者自己的歌曲任务。取消操作上报的生成数量为零。

### Changed

- 普通生歌默认使用 v4.5，提示词上限为 3000 字符，歌词上限为 5000 字符。通过渠道模型映射或 Responses metadata 选择版本时也适用这些限制。
- 仿写默认使用 v3.5，提示词上限为 1000 字符，歌词上限为 3000 字符。纯音乐要求使用 v4.5，且必须提供不超过 3000 字符的非空提示词。
- 开放平台风格的提交和查询接口保留上游任务响应，包括歌曲 ID 和实时播放地址。

### Removed

- 按照开放平台当前支持的模型列表，新请求不再接受 v4.0，并提示调用方改用 v4.5。
- 扩写接口、旧版提交接口和 Responses metadata 均拒绝新建扩写任务。历史扩写任务仍可查询，其歌曲仍可用作仿写参考。

### Fixed

- 完成结算时统计所有状态为 `done` 的歌曲，包括响应中暂未包含音频 URL 的已完成歌曲。失败和已取消的歌曲不计入数量。

### Migration

- 切换至 v4.5 无需重新配置现有 `incho_music` 的每首价格、计费模式或计费表达式；插件没有新增分辨率或模型价格档位。按完成数量结算时，现在会统计所有 `done` 歌曲，包括未返回音频 URL 的歌曲。
- 在渠道中启用 `incho_lyric` 和 `incho_cancel` 前，请分别配置价格：歌词按次生成计费（`clips = 1`），取消操作配置为零费用。若取消操作使用固定按次计费，其单价也必须设为零，因为该模式不使用 `clips`。这些新模型的价格不会自动填入。
- 将原生请求、Responses metadata 和渠道模型映射中显式设置的 v4.0 改为 v4.5。普通生歌和纯音乐请求未指定版本时会使用 v4.5；普通生歌若需使用 v3.5，请显式指定。
- 停止提交扩写请求，开放平台已下线此能力。仿写会生成新歌曲，不能用于续写现有歌曲。
- 查询和取消请求使用网关任务 ID，音频引用使用 `choices` 中返回的网关歌曲 ID。不接受上游原始 ID 或上传文件 ID；引用外部音频时请使用公网音频 URL。
